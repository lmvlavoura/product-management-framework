## 🔄 Continuous Discovery

### O que é?
Processo contínuo de aprender sobre utilizadores, testar ideias e validar assumptions. Não é uma fase, é um hábito.

### Os 3 Pilares (Teresa Torres)

1. **Opportunity Mapping**
   - Mapa visual de customer needs, pain points e desires
   - Conecta outcomes a oportunidades
   - Ajuda a priorizar onde focar

2. **Assumption Testing**
   - Identificar assumptions críticos
   - Testar antes de construir
   - Aprender rapidamente

3. **Weekly Touchpoints**
   - Mínimo 1 touchpoint/semana com clientes
   - Pode ser: entrevista, usability test, data analysis, feedback review
   - Mantém equipa conectada ao utilizador

### Weekly Discovery Rhythm

```
Segunda: Review de feedback da semana anterior
Terça: Customer interview
Quarta: Análise de dados / metrics
Quinta: Usability testing ou prototype feedback
Sexta: Synthesis e planning próxima semana
```

## 🔬 User Research Methods

### Quando usar cada método?

| Método | Quando Usar | Output | Esforço |
|--------|-------------|--------|---------|
| **Customer Interviews** | Descobrir problemas, entender contexto | Insights qualitativos | Medium |
| **Surveys** | Validar hipóteses em escala | Dados quantitativos | Low-Medium |
| **Usability Testing** | Validar soluções, encontrar friction | Issues de usabilidade | Medium |
| **Field Studies** | Entender contexto real de uso | Insights contextuais | High |
| **A/B Testing** | Comparar alternativas, otimizar | Dados de performance | Medium-High |
| **Analytics Review** | Entender comportamento atual | Padrões de uso | Low |
| **Diary Studies** | Capturar experiência over time | Longitudinal insights | High |
| **Card Sorting** | Organizar informação, IA | Estrutura de informação | Low-Medium |

## 🎤 Customer Interviews

### Estrutura de uma Boa Entrevista

#### Preparação (30 min antes)
- [ ] Review do perfil do participante
- [ ] Setup de recording tools
- [ ] Teste de áudio/vídeo
- [ ] Script de perguntas pronto
- [ ] Note-taking setup

#### Abertura (5 min)
```
"Olá [Nome], obrigado por dedicares tempo hoje.

Vou fazer-te algumas perguntas sobre [contexto]. 
Não há respostas certas ou erradas, estou genuinamente 
interessado em entender a tua experiência.

Vou gravar a nossa conversa para não perder detalhes, 
tudo bem? A gravação é só para uso interno e não será partilhada.

Tens alguma questão antes de começarmos?"
```

#### Corpo da Entrevista (40 min)

**Fase 1: Contexto (10 min)**
- Entender o background
- Estabelecer rapport
- Warming up

**Fase 2: Exploração (20 min)**
- Deep dive no problema
- Entender comportamentos atuais
- Descobrir pain points

**Fase 3: Soluções (10 min)**
- Como resolvem hoje
- O que tentaram
- O que funcionou/não funcionou

#### Encerramento (5 min)
```
"Estas foram todas as minhas perguntas. 
Há algo que não perguntei que achas importante?

Posso contactar-te novamente se tiver questões de follow-up?

Muito obrigado pelo teu tempo!"
```

### The Mom Test (Rob Fitzpatrick)

#### ❌ Perguntas Más (Levam a respostas enviesadas)

```
"Gostavas de usar uma app que faz X?"
→ As pessoas dizem que sim para serem simpáticas

"Pagarias €50/mês por isto?"
→ Compromisso hipotético não significa nada

"Que features gostarias de ter?"
→ As pessoas não sabem o que querem

"Achas esta ideia boa?"
→ Pede validação, não informação
```

#### ✅ Perguntas Boas (Focam em comportamento passado)

```
"Conta-me sobre a última vez que tentaste fazer X"
→ Comportamento real

"Como resolves esse problema hoje?"
→ Soluções atuais

"Quanto custa-te esse problema?"
→ Value quantificado

"Mostra-me como fazes isso atualmente"
→ Processo real, não imaginado

"Porque é que isso é importante para ti?"
→ Motivação real
```

### Script Template

```
INTRODUÇÃO
───────────
"Olá [Nome], sou [Teu Nome] e estou a trabalhar em [contexto].
Gostava de entender melhor como [target audience] lida com [problema]."

CONTEXTO
────────
1. Podes descrever o teu papel/responsabilidades?
2. Que tools usas no dia-a-dia para [task]?
3. Como é um dia típico para ti?

PROBLEMA
────────
4. Conta-me sobre a última vez que precisaste de [fazer X]
5. O que torna isso difícil?
6. Que parte desse processo é mais frustrante?
7. Quanto tempo gastas nisso por semana?
8. Já tentaste resolver isso? Como?

SOLUÇÕES ATUAIS
───────────────
9. Que ferramentas/processos usas hoje para isso?
10. O que gostas nessa solução?
11. O que não funciona tão bem?
12. Já experimentaste alternativas?

CONTEXTO DE DECISÃO
────────────────────
13. Se houvesse uma solução melhor, quem decide se a empresa adota?
14. Que critérios usam para avaliar novas tools?
15. Qual é o budget típico para este tipo de solução?

ENCERRAMENTO
────────────
16. Há algo importante sobre [tema] que não perguntei?
17. Conheces outras pessoas que também têm este problema?
```

### Tipos de Perguntas

#### 1. Perguntas Abertas
```
❌ "Usas analytics tools?"
✅ "Como analisas os dados do teu produto?"
```

#### 2. Follow-up Questions
```
"Podes dar-me um exemplo?"
"Porque é que isso aconteceu?"
"Como te sentiste quando isso aconteceu?"
"O que fizeste a seguir?"
```

#### 3. Perguntas de Comportamento
```
"Mostra-me o teu processo"
"Quando foi a última vez que..."
"Com que frequência..."
"Quanto tempo demora..."
```

### Red Flags em Entrevistas

🚩 "Seria ótimo se..."
🚩 "Toda a gente que conheço precisa disso"
🚩 "Definitivamente pagaria por isso"
🚩 "Adoro a ideia!"
🚩 Respostas muito genéricas
🚩 Falar mais do futuro que do passado
🚩 Não conseguir dar exemplos específicos

### Green Lights

✅ Exemplos específicos e detalhados
✅ Frustração genuína ao descrever problema
✅ Já tentou múltiplas soluções
✅ Gasta tempo/dinheiro no problema hoje
✅ Pede para ser early tester
✅ Oferece apresentar outros potenciais users

## 💼 Jobs-to-be-Done (JTBD)

### O Framework

**Conceito Core**: People don't buy products, they hire them to get a job done.

### JTBD Statement Format

```
Quando [situação/contexto]
Eu quero [motivação]
Para que eu possa [outcome desejado]
```

### Exemplo: Spotify

```
Quando estou no ginásio
Eu quero ouvir música energética
Para que eu possa manter-me motivado durante o treino
```

### Exemplo: Analytics Platform

```
Quando preciso de apresentar resultados ao CEO
Eu quero aceder rapidamente a métricas-chave
Para que eu possa mostrar o impacto do nosso trabalho
```

### Os 3 Tipos de Jobs

#### 1. Functional Jobs
O que o utilizador quer fazer/completar

```
Exemplos:
- Analisar performance de produto
- Comunicar com a equipa
- Organizar tarefas
- Aprender uma nova skill
```

#### 2. Social Jobs
Como o utilizador quer ser percecionado

```
Exemplos:
- Parecer competente
- Ser visto como inovador
- Gain recognition
- Fazer parte de uma comunidade
```

#### 3. Emotional Jobs
Como o utilizador quer sentir-se

```
Exemplos:
- Sentir-se no controlo
- Reduzir ansiedade
- Ganhar confiança
- Evitar frustração
```

### Competing Solutions Analysis

Para cada JTBD, mapear:

| Solução | Pro | Contra | "Hiring" Trigger |
|---------|-----|--------|------------------|
| Fazer manualmente | Controlo total | Demorado | Quando há tempo |
| Tool A | Rápido | Caro | Quando budget aprovado |
| Tool B | Barato | Limitado | Quando custo importa |
| Workaround | Grátis | Frágil | Quando sem budget |
| Não fazer nada | Sem esforço | Problema persiste | Quando não é prioridade |

## 👤 User Personas

### O que NÃO é uma Persona

❌ Descrição demográfica
❌ Foto stock com nome genérico
❌ Lista de hobbies irrelevantes
❌ Criada sem research
❌ Baseada em assumptions

### O que É uma Persona

✅ Baseada em research real
✅ Representa padrões de comportamento
✅ Foca em goals e motivações
✅ Inclui contexto relevante
✅ É acionável para design/product decisions

## ✅ Problem Validation

### O Que é?
Confirmar que o problema é:
1. Real (pessoas têm-no)
2. Frequente (acontece regularmente)
3. Valioso (importa o suficiente)
4. Underserved (soluções atuais são inadequadas)

### Problem Score Framework

Rate cada problema de 1-10 em:

| Critério | Score | Notas |
|----------|-------|-------|
| **Frequency** | /10 | Com que frequência acontece? |
| **Severity** | /10 | Quão doloroso é? |
| **Market Size** | /10 | Quantas pessoas têm? |
| **Willingness to Pay** | /10 | Pagariam para resolver? |
| **Competition** | /10 | (Inverso) Quão bem servido está? |

**Total**: __/50

- **40-50**: Problema excellente
- **30-39**: Problema bom
- **20-29**: Problema OK
- **<20**: Reconsiderar

### Validation Tests

#### Test 1: The Fake Door Test
```
Setup: Landing page descrevendo solução
Call-to-action: "Join waitlist"
Success: X% de visitors registam interesse
Threshold: Definir antes (ex: >5% = validado)
```

#### Test 2: The Manual First MVP
```
Setup: Fazer manualmente o que o produto faria
Oferecer a 5-10 clientes
Success: Customers pagam e ficam engaged
Learn: O que é realmente essencial vs nice-to-have
```

#### Test 3: The Concierge Test
```
Setup: Serviço white-glove personalizado
Work closely com early customers
Success: Retention após remover white-glove
Learn: What needs to be automated
```

## 🎨 Solution Validation

### O Que é?
Depois de validar o problema, validar que a solução proposta:
1. Resolve o problema
2. É usável
3. É desejável
4. É viável

### Fidelity Ladder

```
Low Fidelity          →          High Fidelity
─────────────────────────────────────────────────
Sketch                          Production Code
Paper Prototype                 Beta Launch
Clickable Mockup                Full Product
Interactive Prototype
```

Começar sempre low-fidelity para aprender rápido e barato.

### Solution Testing Methods

#### 1. Prototype Testing (Low-fi)
```
Materials needed:
- Figma/Sketch mockups
- Prototype interativo
- 5-8 participantes

Process:
1. Apresentar contexto
2. Task-based testing: "Imagina que precisas de X, mostra-me como farias"
3. Think-aloud protocol
4. Debrief questions

Métricas:
- Task success rate
- Time to complete
- Number of errors
- Satisfaction rating
```

#### 2. Smoke Test
```
Setup:
- Marketing campaign
- Landing page
- CTA para "Get Early Access"

Success criteria:
- Conversion rate > X%
- Y signups em Z dias

Budget: €500-1000
Timeline: 1-2 semanas
```

#### 3. Beta Program
```
Participants: 10-50 early adopters
Duration: 4-8 semanas
Engagement:
- Weekly check-ins
- Feature surveys
- Usage analytics

Success metrics:
- Weekly Active Users
- Feature adoption
- NPS score
- Qualitative feedback
```

### Usability Testing Script

```
PRÉ-TESTE (5 min)
─────────────────
"Vou mostrar-te um protótipo de algo em que estamos a trabalhar.
Lembra-te que estamos a testar o produto, não a ti.
Pensa em voz alta enquanto usas.
Se ficares bloqueado, não é culpa tua."

TASKS (30 min)
──────────────
Task 1: [Scenario específico]
"Imagina que precisas de [goal]. Como farias?"

[Observar em silêncio. Não ajudar.]
[Fazer probe questions: "O que estás a pensar?" "O que esperas que aconteça?"]

Task 2: [Next scenario]
[...]

DEBRIEF (10 min)
────────────────
"O que achaste mais fácil?"
"O que foi mais confuso?"
"O que mudarias?"
"Comparado com [competidor], como se compara?"
"Numa escala 1-10, probabilidade de usar?"
```

### Solution Validation Checklist

- [ ] 5+ prototype tests realizados
- [ ] Task success rate > 80%
- [ ] Zero showstopper issues
- [ ] Net Promoter Score > 30
- [ ] Willingness to pay validada
- [ ] Value proposition ressonou com users
- [ ] Competitive advantage clara
- [ ] Technical feasibility confirmada
- [ ] Go-to-market strategy defined

## ✅ Discovery Checklist

### Problem Discovery
- [ ] 10+ customer interviews realizadas
- [ ] Problema claramente articulado
- [ ] JTBD mapeado
- [ ] Personas criadas (2-4)
- [ ] Competing solutions identificadas
- [ ] Problem score > 30/50
- [ ] Market size validado

### Solution Discovery
- [ ] 3+ solution concepts explorados
- [ ] Prototype criado
- [ ] 5+ usability tests
- [ ] Feedback incorporado
- [ ] Beta com 10+ users
- [ ] Metrics baseline estabelecidas
- [ ] Go/No-go decision tomada
