## Templates Essenciais

### Template 1: Product Vision
```
Para [target customer]
Que [statement of need]
O [product name] é [category]
Que [key benefit]
Ao contrário de [competitor]
O nosso produto [differentiation]
```

### Template 2: User Story
```
Como [persona]
Eu quero [ação]
Para que [benefício]

Acceptance Criteria:
- [ ] Critério 1
- [ ] Critério 2
- [ ] Critério 3
```

### Template 3: Feature Brief
```
# Feature: [Nome]

## Problem
[O que queremos resolver]

## Solution
[Como vamos resolver]

## Success Metrics
- Primary: [KPI] from X to Y
- Secondary: [KPI] from X to Y

## Scope
In Scope:
- [Item 1]
- [Item 2]

Out of Scope:
- [Item 1]
- [Item 2]

## Timeline
- Design: [dates]
- Development: [dates]
- Launch: [date]
```

## Cheat Sheet: Decisões Rápidas

### "Devo construir esta feature?"

**Pergunta 1**: Resolve um problema validado?
- ❌ Não → Voltar a Discovery
- ✅ Sim → Próxima pergunta

**Pergunta 2**: Alinha com estratégia?
- ❌ Não → Deprioritizar
- ✅ Sim → Próxima pergunta

**Pergunta 3**: RICE score > 200?
- ❌ Não → Reconsiderar
- ✅ Sim → Próxima pergunta

**Pergunta 4**: Capacity disponível?
- ❌ Não → Backlog ou cortar outra coisa
- ✅ Sim → BUILD IT!

---

### "Como priorizar entre features?"

```
Use RICE:
1. Score cada feature
2. Rank por RICE score
3. Adjust por:
   - Strategic importance
   - Dependencies
   - Team expertise
4. Top 3 = NOW
```

## Red Flags 🚩

### No Product
🚩 Construir features sem validar problema
🚩 "Eu acho que users querem..."
🚩 Copiar competidores sem raciocínio
🚩 Feature requests = roadmap
🚩 Sem falar com users regularmente

### No Prioritization
🚩 Tudo é prioridade
🚩 "CEO disse, então fazemos"
🚩 Sem critério claro de decisão
🚩 Não há backlog, só "next sprint"

### No Metrics
🚩 Não saber se feature teve impacto
🚩 Só olhar para vanity metrics
🚩 Nenhuma métrica de retention
🚩 Não fazer A/B tests

## Últimas Dicas

### Para Founders
1. **Fala com users**: Mínimo 3x/semana
2. **Start simple**: MVP, não produto perfeito
3. **Say no often**: Focus é tudo
4. **Measure everything**: Se não medires, não sabes

### Para PMs Júnior
1. **Learn by doing**: Templates ajudam, prática ensina
2. **Ask why**: Sempre questiona decisions
3. **Stay user-centric**: Eles são a bússola
4. **Own outcomes**: Não apenas outputs

### Para Teams
1. **Align on vision**: Todos entendem o porquê
2. **Share context**: Transparência ganha
3. **Celebrate learning**: Não apenas wins
4. **Ship often**: Small, frequent releases
